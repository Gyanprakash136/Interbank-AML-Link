AML COLLABORATION FOR BANKS

Find overlapping suspects across banks. Keep transaction data in-house.

SignalMesh lets banks compare flagged entities using Private Set Intersection, so analysts can see where their cases overlap without sending transaction records to a central party.

Matches are leads for analyst review, not findings of financial crime.

Explore the platform How it works

What each bank keeps, and what it compares

Every institution analyzes its own transaction network. When a bank chooses to compare, only tokens for flagged entities enter the private matching step.

Local risk analysis

Builds a graph from a bank's own transactions and surfaces indicators an analyst can inspect and explain.

Private matching

Uses a PSI protocol to find entities two banks have both flagged, without either side sharing its full candidate list.

Session audit trail

Records each collaboration session in a hash-chained ledger. The ledger shows tampering within the local chain; it is not an external proof.

How it works

Collaboration follows three sequential phases designed to keep raw customer records inside the originating institution.

01

Analyze locally

Each bank identifies candidate entities and risk indicators from its own data.

02

Match privately

Two banks run PSI to find exact overlaps between their candidate sets.

03

Review with context

Each bank keeps its own graph and evidence, and analysts decide what to do next.

What is shared and what is not

Banks exchange protocol messages, not transaction rows or graph structures. A match does reveal which entities two participants have in common, and session metadata is written to the audit ledger. These are the disclosure boundaries of the prototype. Outputs support analyst review and do not determine that a crime occurred.

Bank-local data

Remains inside each bank

  • Raw customer account records, transaction rows, and timestamps
  • Full local transaction graphs and subgraphs
  • Unmatched candidate entities and non-flagged accounts
Exchanged or logged

Observable session telemetry

  • Serialized cryptographic protocol messages (ServerSetup, Request, Response)
  • Matching token identifiers revealed to the participating pair
  • Session identifiers, message byte counts, and execution timings in the audit ledger

Architecture

Graph analysis and detection run inside each bank's own worker process. A coordinator relays serialized PSI messages and logs session metadata. It does not receive transaction rows or local graphs.

Research prototype

Prototype scope

SignalMesh is currently demonstrated with synthetic datasets and separate local processes on one development machine. Network transport between institutions, TLS/mutual authentication, independent institutional deployment, external anchoring of the audit chain, and IBM LinuxONE compatibility are not yet implemented or verified.
